## 🧠 Tư duy thiết kế hệ thống

Mình hướng tới việc xây dựng phần mềm **dễ mở rộng, dễ bảo trì và tách bạch trách nhiệm rõ ràng**, dựa trên các nguyên tắc:

<table>
<tr>
<td width="50%" valign="top">

**🏛️ Clean Architecture**
- Tách lớp Domain / Application / Infrastructure / Presentation
- Dependency Inversion giữa các tầng
- Dễ test, dễ thay đổi công nghệ ở tầng ngoài

**🧩 SOLID Principles**
- **S**ingle Responsibility — mỗi class một nhiệm vụ
- **O**pen/Closed — mở để mở rộng, đóng để sửa đổi
- **L**iskov Substitution — kế thừa an toàn
- **I**nterface Segregation — interface nhỏ, đúng mục đích
- **D**ependency Inversion — phụ thuộc vào abstraction

</td>
<td width="50%" valign="top">

**🧱 Microservices & Messaging**
- Tách service theo domain nghiệp vụ (DDD)
- Giao tiếp bất đồng bộ qua Kafka / RedisMQ
- API Gateway, service discovery cơ bản

**⚙️ DevOps & Vận hành**
- Container hoá với Docker, orchestrate cơ bản
- CI/CD pipeline với Jenkins & GitHub Actions
- Triển khai & giám sát trên Azure / VPS

</td>
</tr>
</table>
